大模型系统与性能优化

从 Transformer 和 GPU 基础，走到推理引擎、分布式通信、性能剖析与可复现实验。目标不是记住术语，而是能定位瓶颈、验证假设并交付稳定服务。

建议周期：12–16 周主线：推理系统方式：理论 + 实验

先建立正确的学习方式

每次优化都遵循同一条链路：建立基线 → 固定变量 → 找到瓶颈 → 修改一个因素 → 复测延迟、吞吐、稳定性和成本。

性能结论必须绑定模型、硬件、输入输出长度、并发度、软件版本和服务目标。没有这些上下文，“某配置更快”通常不能迁移到另一套环境。

阶段学习路线

01第 1–2 周

编程、数学与系统基础

  • Python、Linux、Shell、Git；补齐 C/C++ 的内存、线程、锁和异步执行。
  • 掌握线性代数、概率统计、微积分的必要部分，以及操作系统、网络、数据结构。
  • 理解进程、线程、NUMA、I/O、复杂度和基本并发模型。
02第 3–4 周

深度学习与 Transformer

  • 能解释 Attention、MHA、GQA、RoPE、RMSNorm、MoE 和 Transformer 训练流程。
  • 理解 Prefill、Decode、KV Cache，以及参数、激活、序列长度和 batch 对显存的影响。
  • 手写一个小型 Transformer，用 PyTorch 跑通训练或推理。
03第 5–6 周

GPU、CUDA 与硬件瓶颈

  • 学习 SM、Tensor Core、显存层级、带宽、FLOPs、算术强度和 Roofline。
  • 理解 kernel、thread block、shared memory、stream、event 和同步。
  • 认识 PCIe、NVLink、RDMA、CPU/NUMA、存储对服务的影响；按实际环境补充 CUDA、CANN 等平台知识。
04第 7–9 周

推理引擎与服务调度

  • 深入 Prefill、Decode、Chunked Prefill、Continuous Batching、PagedAttention。
  • 掌握 Prefix Cache、量化（BF16、FP8、INT8、INT4）和 Speculative Decoding 的适用条件。
  • 运行并阅读 vLLM、SGLang 或 TensorRT-LLM，观察请求队列、KV Cache 和 batch 调度。
05第 10–11 周

分布式执行

  • 理解 TP、PP、DP、EP 的通信量、显存代价、适用场景和扩展边界。
  • 学习 NCCL、AllReduce、AllGather、All-to-All、通信拓扑，以及通信计算重叠。
  • 了解 checkpoint、容错、滚动升级、Kubernetes、GPU 调度和服务路由。
06第 12–16 周

Profiling、压测与容量规划

  • 使用 Nsight Systems、Nsight Compute、PyTorch Profiler、nvidia-smi 定位瓶颈。
  • 设计固定 workload 的 A/B 实验，观察 P50、P95、P99、错误率和结果稳定性。
  • 从绝对 SLO 出发确定容量，分别报告计算、显存、通信、排队和调度因素。

性能指标速查

TTFTTime to First Token，首 token 延迟，常受排队和 Prefill 影响。
ITL / TPOT生成 token 间隔，反映 Decode 阶段的交互体验。
吞吐量tokens/s 或 requests/s，必须注明输入输出 token 口径。
并发度同时处理的请求数；高并发不等于满足用户 SLO。
P95 / P99尾延迟比平均值更能暴露排队、抖动和资源争用。
扩展效率增加 GPU 后的实际收益，需结合通信开销和稳定性判断。

实践项目

项目 1：单卡推理基线

  • 部署一个 7B 左右模型，固定 prompt、输出长度和并发档位。
  • 记录 TTFT、ITL、吞吐、P95、错误率、显存和 GPU 利用率。
  • 比较 batch size、上下文长度和 BF16/量化的变化。

项目 2：KV Cache 与调度观察

  • 改变上下文长度和并发度，画出显存、TTFT、ITL、吞吐曲线。
  • 阅读 vLLM 或 SGLang 的 KV Cache、PagedAttention 和调度代码。
  • 标记饱和点、错误率上升点和排队时间突变点。

项目 3：多卡并行 A/B

  • 在相同 workload 下比较 TP、DP，模型适配时再评估 EP/PP。
  • 采集通信时间、链路带宽、显存和扩展效率，不只比较 tokens/s。
  • 输出硬件拓扑、软件版本、配置和原始日志，保证结果可复现。

项目 4：端到端服务化

  • 在 Kubernetes 上部署推理服务，接入监控、限流、健康检查和故障恢复。
  • 用真实请求分布压测，分别验证稳定性门槛和容量 SLO。
  • 形成一份包含假设、配置、指标、图表、结论和限制的性能报告。
